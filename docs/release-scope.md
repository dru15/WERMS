# Runnable release 0.6 — India operations and ML research

The main application uses 4,480 Dehradun OSM nodes, 4,547 segments, turn-aware hazard-aware A*, durable full-party capacity reservations, staff identity/roles, incident/resource workflows, weather context and a non-destructive resilience lab. MapLibre/OpenFreeMap replaces the failed/blurred raster basemap; errors and retry remain visible. Destinations are mapped landmarks with synthetic capacity, not verified emergency shelters.

The offline pipeline has actually processed the public FireCastRL release and trained Logistic Regression, Gradient-Boosted Trees and a two-layer GRU with attention. The delivered report, model card and interactive observatory show measured counts, causal 60×15 sequences, separated training/validation/calibration/test cohorts, AUROC/AUPRC/recall/F1 and calibration evidence. Large training data/output remain ignored by Git; a verified 974 KB research bundle with models, selected case exports, attribution and hashes is included in the Python package, allowing fresh-clone inference without downloading training data. It is not operational model approval. Missing custom artifacts produce an explicit unavailable/not-trained state.

The measured CSV differs from advertised counts: 126,799 windows / 9,509,925 rows; 126,442 accepted causal sequences after quarantine/deduplication. Model performance and class imbalance are reported honestly. Residual source-family leakage cannot be disproved because original incident IDs are absent. Calibration remains unsuitable for operational probability claims.

PostGIS 3.6.2 on portable PostgreSQL 17.11 has been run locally and tested against real geometry. It indexes OSM roads, evaluates valid fire polygons using `ST_Intersects`, and projects genuine model scores in the separate California research replay. Fire-perimeter publication/invalidation and all capacity/bookings remain serialized in SQLite; this is not a full PostgreSQL operational-store migration. Schema 2 prevents older binaries ignoring newly published constraints. No Windows service or hardware is required.

The US replay uses a declared 3 km experimental support neighbourhood and a source case outside the evaluation cohort. It demonstrates model-to-spatial-cost integration on real OSM roads, with no reservation or claimed historical incident reconstruction. US model scores are refused for India routing. There is no trained/validated India forecast feed, live satellite-fire ingestion, fire-spread prediction, official shelter certification or established patentability.

Native execution, saved-model inference parity, real PostGIS geometry behavior, backend invariants, frontend interactions and production web build are verified. Docker configuration includes CPU inference and a PostGIS dependency, but cannot be execution-verified because Docker is absent. Redis remains optional/unused. Authoritative India data, geographic validation, external evaluation, production hardening and novelty research remain future work.
