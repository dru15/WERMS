# Runnable project release: 0.4

This release delivers a connected software research pilot: real mapped roads, direction/turn-aware routing, shared closures, durable capacity reservations, shelter arrival and administration, staff identity/roles, incident management, resource allocation, and audit history. It runs locally without paid keys, hardware, Docker, PostGIS, or Redis. Internet access is needed for visible map tiles; imported roads and local operational data remain available if tiles fail.

The implemented resource lifecycle is register → available → dispatched → acknowledged → completed/cancelled → available. Incidents progress reported → acknowledged → resolved, with priority escalation and version checks. Shelter allocation considers full party demand and the configured 90% admission threshold; occupancy corrections cannot overfill a site. Transactions, idempotency, and uniqueness constraints enforce those invariants rather than browser counters.

The historical requirements baseline describes a broader research programme. The current release deliberately uses a zero-heuristic shortest-path search on an imported graph rather than an unvalidated geographic A* heuristic. SQLite is the implemented persistence adapter. Resource assignments are a command-desk record with manually entered instructions; there is no responder-specific path optimizer or external acknowledgement transport. Incident ingestion is manual and records provenance; automated fire/weather ingestion and replay are not implemented. Predictive ML is disabled and no trained or validated model is shipped.

Remaining research work includes authoritative hazard/closure sources, validated assembly sites, larger-area navigation and responder routing, PostGIS migration, calibrated predictive models with leakage-controlled evaluation, scenario/latency benchmarks, user/accessibility studies, deployment hardening, and a prior-art/novelty investigation. These are limits on research and operational claims, not hidden fallbacks in the runnable app. No claim of patent eligibility or real-world evacuation safety is made.

Verification comprises backend invariant/API tests, frontend interaction tests, static checks, and a production web build. Container configuration is supplied but cannot be execution-verified on the current workstation because Docker is unavailable. Follow the demo guide for a repeatable presentation of the implemented behavior.
